# Changelog — Sales Analyst Dashboard

รูปแบบเวอร์ชัน: **Semantic Versioning** `MAJOR.MINOR.PATCH`
- **MAJOR** = เปลี่ยนโครงสร้าง/ดีไซน์ใหญ่ (breaking)
- **MINOR** = ฟีเจอร์ใหม่ (ไม่ทำของเดิมพัง)
- **PATCH** = แก้บั๊ก / แก้สูตรคำนวณ / แก้ UI / performance

สถานะ: `DRAFT` → `TESTING` → `STABLE` → `DEPRECATED`
กติกา: **ห้ามมาร์ก STABLE เอง** ต้องรอผู้ใช้ยืนยัน "Approved" / "ใช้งานได้" / "Stable"

Snapshot สมบูรณ์ที่รันได้ของแต่ละเวอร์ชันเก็บไว้ใน `versions/vX.Y.Z/`

### แท็บ YTD: "พยากรณ์สิ้นเดือน" → "พยากรณ์สิ้นปี" (Average sale/Month × 12)
ผู้ใช้ขอว่าเวลาเลือกแท็บ YTD ช่อง "พยากรณ์สิ้นเดือน" ควรเปลี่ยนเป็น "สิ้นปี" โดยใช้สูตร Average sale/Month

- **ตารางรายสาขา + ตามประเภทร้าน** — หัวคอลัมน์เปลี่ยนตามแท็บอัตโนมัติ (เหมือนที่คอลัมน์ ยอด/วัน ↔ ยอด/เดือน
  ทำอยู่แล้ว): แท็บ MTD = **"พยากรณ์สิ้นเดือน"** (ยอด/วัน × จำนวนวันในเดือน — สูตรเดิม ไม่เปลี่ยน),
  แท็บ YTD = **"พยากรณ์สิ้นปี"** (ยอด/เดือน × 12), แท็บ Daily/Custom ยังขึ้น "—" เหมือนเดิม
  (สองแท็บนี้ไม่มี "ช่วงเต็ม" ที่นิยามได้ชัด)
  → เดิมแท็บ YTD ขึ้น "—" ทั้งคอลัมน์ ใช้ประโยชน์ไม่ได้เลย
- **การ์ด KPI ด้านบน** — แท็บ YTD เปลี่ยนจาก "พยากรณ์สิ้นเดือน (Estimated Landing)" เป็น
  **"พยากรณ์สิ้นปี (Estimated Landing)"** = ยอดขาย/เดือน × 12 พร้อมบรรทัดย่อย: ปี, จำนวนเดือนที่มียอดขาย
  (เช่น 4/12 เดือน • เหลือ 8 เดือน), ยอดสะสม, ยอด/เดือน และเทียบ **เป้าทั้งปี** (ผลรวมเป้า ม.ค.–ธ.ค.
  ของสาขาที่อยู่ในตัวกรอง) แทนเป้ารายเดือน — แท็บ MTD/Daily/Custom ยังเป็นพยากรณ์สิ้นเดือนสูตรเดิมทุกอย่าง

### ⚠️ เปลี่ยนนิยาม KPI: ตัวหารของ "ยอด/เดือน" ในแท็บ YTD
- **เดิม:** ยอด/เดือน = ยอดขาย YTD ÷ **จำนวนเดือนปฏิทินที่ผ่านมา** (ม.ค. ถึงเดือนของ "ณ วันที่")
- **ใหม่:** ยอด/เดือน = ยอดขาย YTD ÷ **จำนวนเดือนที่มียอดขายจริงในช่วงที่เลือก**
- **ทำไมต้องแก้:** ถ้าอัปข้อมูลไม่ครบทั้งปี (เช่นมีแค่ มิ.ย.–ก.ย. 4 เดือน แต่ตอนนี้เดือน 9) สูตรเดิมหารด้วย 9
  = เฉลี่ยต่ำกว่าความจริง 2.25 เท่า เพราะนับเดือนที่ "ไม่เคยอัปข้อมูล" เป็นเดือนที่ขายได้ 0 บาท
  และทำให้พยากรณ์สิ้นปีในตาราง (฿334M) ไม่ตรงกับการ์ด KPI ด้านบน (฿752M) ทั้งที่ชื่อเดียวกัน
- **ผลกระทบ:** ถ้าอัปครบทุกเดือนตั้งแต่ ม.ค. ตัวเลขเท่าเดิมทุกประการ (จำนวนเดือนที่มียอดขาย = เดือนปฏิทินที่ผ่านมา)
  จะต่างก็ต่อเมื่อข้อมูลไม่ครบ ซึ่งกรณีนั้นค่าใหม่ถูกกว่า
- ใช้ตัวหารเดียวกันทุกแถว ทำให้ผลรวมรายสาขายังเท่ากับแถว Total เหมือนเดิม (ทดสอบแล้ว ต่างกันแค่การปัดเศษ)
  และตรงกับตัวหารของการ์ด "ยอดขาย/เดือน (Sale/Month)" พอดี

### แก้ไข Store Type ได้เองในแดชบอร์ด (ไม่ต้องอัปโหลดไฟล์)
ผู้ใช้แจ้งว่า Store Type ตอนนี้แก้ไม่ได้เลยในแดชบอร์ด (ฟีเจอร์อัปโหลด Template Store Type ของ v2.1.0
หายไปตอนย้อนกลับไป v2.0.0 และไม่เคยถูกนำกลับมา) และขอ tool ที่แสดงว่ามียอดขายที่สาขาไหนบ้าง
แล้วเลือก Store Type เองตรงนั้นได้เลย — จึงสร้างตัวแก้ไขแบบ inline บนตาราง **"รายละเอียดตามสาขา"**
(หน้า ยอดขาย → การ์ด "ยอดขายและ Retail KPI รายสาขา") ซึ่งมีอยู่แล้วว่าสาขาไหนมียอดขายเท่าไหร่:

- ปุ่ม **"✏️ แก้ไข Store Type"** เปิด/ปิดโหมดแก้ไข — เปิดแล้วคอลัมน์ "ประเภท" ของแต่ละสาขาจะกลายเป็น
  dropdown ให้เลือกจากประเภทที่มีอยู่แล้วทั้งหมด, **"+ เพิ่มประเภทใหม่..."** (พิมพ์ชื่อเองได้), หรือ
  **"— ค่าเริ่มต้นของระบบ —"** (ล้าง override กลับไปใช้ค่าเริ่มต้นของระบบ/ไลบรารีในตัว)
- เลือกแล้ว **บันทึกอัตโนมัติทันที** — ไม่ต้องกดปุ่ม Save เพิ่ม
- ค่าที่ตั้งเก็บใน `S.storeTypeLib` (Store_Code → ประเภท), sync ขึ้นคลาวด์อัตโนมัติถ้าเข้าสู่ระบบอยู่
  (`company/main/meta/storeTypes`), ดึงกลับมาใช้บนอุปกรณ์อื่นอัตโนมัติตอนเข้าสู่ระบบ/รีเฟรชจากคลาวด์
- ลำดับความสำคัญของค่า Store Type ต่อสาขา (เปลี่ยนจากเดิม): **ค่าที่ผู้ใช้ตั้งเอง > คอลัมน์ Store Type
  ในไฟล์ (ถ้ามี, พบน้อยมาก) > ค่าเริ่มต้นในไลบรารีของระบบ > "—"** — ค่าที่ผู้ใช้ตั้งเองชนะเสมอ เพราะเป็น
  การตัดสินใจที่ชัดเจนของผู้ใช้เอง แม้ไฟล์จะมีคอลัมน์นี้อยู่ก็ตาม
- การตั้งค่ามีผลย้อนหลังกับทุกเดือนที่โหลดไว้ในเครื่อง (ไม่ใช่แค่เดือนที่กำลังดู) และมีผลกับเดือนที่ดึงจาก
  คลาวด์เพิ่มทีหลังด้วย (ผ่าน `applyStoreTypeLibToMonths` ที่เรียกหลังโหลดเดือนใหม่ทุกจุด)
- ปุ่ม "— ค่าเริ่มต้นของระบบ —" รีเซ็ตกลับไปที่ไลบรารีในตัว (`STORE_TYPE_LIB`) เท่านั้น — ถ้าไฟล์เดิมมี
  คอลัมน์ Store Type ของตัวเอง การรีเซ็ตจะไม่ดึงค่านั้นกลับมา (เพราะระบบไม่เก็บค่าดิบจากไฟล์แยกไว้ต่างหาก
  หลัง parse) ซึ่งในทางปฏิบัติแทบไม่กระทบ เพราะไฟล์ยอดขายจริงที่ใช้อยู่ (Mer-Raw) ไม่มีคอลัมน์นี้อยู่แล้ว

### ทดสอบ (Playwright headless)
- อัปโหลดไฟล์ทดสอบ → เปิดโหมดแก้ไข → เห็น `<select>` ในคอลัมน์ประเภทของสาขาที่มียอดขายจริง ✅
- เลือก "+ เพิ่มประเภทใหม่..." พิมพ์ชื่อใหม่ → ทุกแถวของสาขานั้นเปลี่ยนเป็นประเภทใหม่ทันที, สาขาอื่นไม่กระทบ ✅
- กด "— ค่าเริ่มต้นของระบบ —" → override ถูกลบ, กลับไปใช้ค่าเริ่มต้นของไลบรารี ✅
- ตั้งค่า, บันทึก (`save()`), รีโหลดหน้า (`load()`) → override ยังอยู่ครบ (persist ผ่าน localStorage) ✅
- จำลองสถานะเข้าสู่ระบบ (`cloudUser`) แล้วเรียก `setStoreTypeOverride` + `pullAllFromCloud` → ไม่มี error ✅
- ไม่มี console error / page error ตลอดการทดสอบ

### Known issues
- ยังไม่ได้ทดสอบซิงค์ข้ามอุปกรณ์จริงกับ Firebase จริง (ทดสอบผ่าน stub เท่านั้น เหมือนฟีเจอร์อื่นๆ ในระบบ)

### 2) Bill Count / Transaction Count — คิดระดับ "ธุรกรรม" (ไม่ใช่นับแถว)
- **นิยาม:** 1 บิล = 1 คู่ `Store_Code + Receipt_No` ที่มีรายการขายจริง คือ `SUM(MAX(Sold_Qty,0)) > 0`
  - Receipt เดียวมีหลายรายการสินค้า → นับเป็น **1 บิล** (ไม่ใช่หลายบิล)
  - บิลคืนสินค้าล้วน (qty ติดลบทั้งใบ) และบิล qty=0 → **ไม่นับเป็นบิลขาย**
  - ใช้คีย์ `Store_Code + Receipt_No` เผื่อ Receipt_No ซ้ำข้ามสาขา
- **ของเดิม (fallback):** นับ Receipt_No ที่ไม่ซ้ำทั้งหมด → เกินจริง (นับบิลคืนด้วย)
- **KPI ที่ผูกกับนิยามใหม่นี้ทั้งหมด:** จำนวนบิล (Total/by Store/by Type/by Promo),

- **KPI:** ยอดขาย (Net), จำนวนชิ้น, GP, GP%, ASP, ATV, UPT, จำนวนบิล (SUM Bill Count, fallback = distinct Receipt_No), Sale/Day ↔ Sale/Month (ตาม view), พยากรณ์สิ้นเดือน
- **กราฟ:** แท่ง = ยอดขายราย Store Type · โดนัท = brand-aware product mix (GOODR → ModelName, NATGEO → Subclass)
- **ตาราง:** ยอดขายรายสาขา (เปลี่ยนตามช่วง Daily/MTD/YTD), sort ได้ทุก dimension
- **หน้า Stock:** Stock by store (Stock Net / Stock Cost / MOH), brand-aware grouping, honor store-type filter
- **ข้อมูล:** อ่าน .xlsx (SheetJS), Firestore + Google Sign-in, gzip compression (pako), service worker network-first
- **Aging pipeline (Flag_O):** parse + persist + cloud-sync ไว้แล้ว แต่ยังไม่แสดง UI (dormant)

### KPI definitions (นิยามที่ตรึงไว้ — ห้ามเปลี่ยนเงียบ ๆ)
| KPI | นิยาม |
|---|---|
| ยอดขาย (Net) | ผลรวม Netsale_ExcVAT |
| จำนวนชิ้น | ผลรวม Sold_Qty |
| GP | Net − COGS (Margin_Value) |
| GP% | GP / Net |
| ASP | Net / จำนวนชิ้น |
| ATV | Net / จำนวนบิล |
| UPT | จำนวนชิ้น / จำนวนบิล |
| จำนวนบิล | SUM(Bill Count column); ถ้าไม่มีคอลัมน์ → distinct Receipt_No |
| Sale/Day | Net / จำนวนวันที่มีการขาย |
| Sale/Month | Net / จำนวนเดือน (มุมมอง YTD) |
| พยากรณ์สิ้นเดือน | (ยอด MTD / วันที่ผ่านมา) × จำนวนวันในเดือน |
| Stock Cost | ผลรวม Cost Amount |
| MOH | Stock / ยอดขายเฉลี่ยต่อเดือน |
